# Contributing to metadatarr

Thanks for contributing! This is a small, focused library — clean providers,
typed models, silent-failure behaviour. Keep changes small and reviewable.

## Branch & PR flow

- Work on a feature branch off `dev`. **Never push to `dev` or `master`
  directly.**
- Open a PR into `dev`. `dev` is the alpha line; stable releases promote `dev`
  to `master` via a release PR.
- Keep PRs small and single-purpose. Keep the test suite green at every step.

## Commit messages → automatic versioning

The version is computed from your **conventional-commit** prefixes — you never
edit it by hand. PR labels can override the prefix.

| Prefix | Bump | Example |
|---|---|---|
| `feat:` | minor | `feat: add Deezer provider` |
| `fix:` | patch | `fix: tvdb provider swallows timeouts` |
| `feat!:` / `BREAKING CHANGE:` | major | `feat!: rename ExternalIds.tvdb to tvdb_series` |
| `docs:` / `chore:` / `test:` / `refactor:` | alpha-only | `docs: add testing guide` |

### Do not edit `version.py`

`metadatarr/version.py` is generated by the release automation from the commit
history (it uses the OVOS `VERSION_BLOCK` format). Editing it by hand will
conflict with the bump and is reverted. Likewise, **never** manually publish to
PyPI — the merge-to-`master` workflow does the release.

## Tests

```bash
pip install .[test]
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q
```

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` matches CI (no third-party pytest plugins).
All tests must be **offline** — patch the transport, never hit the network. See
[docs/testing.md](docs/testing.md).

### CI / what runs on your PR

Pushing a PR triggers the shared `gh-automations` workflows: build + tests,
coverage, lint, license check, pip-audit, and a release preview. Match them
locally before you push:

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q   # tests
python -m pytest --cov=metadatarr                       # coverage
```

## Adding a provider

Follow [docs/add-provider.md](docs/add-provider.md). In short: subclass
`MetadataProvider`, declare the three routing axes, implement `is_available()`
and a never-raising `lookup()`, emit only canonical mediavocab values, and
`register()`. Add an offline test (mock HTTP or committed fixture).

## Code conventions

- **Pydantic V2** models, typed everywhere.
- **Silent failure**: providers and clients return `[]` / `None` on error — they
  never raise into the caller. Log with `LOG.warning(... query=...)` for expected
  transport failures and `LOG.exception(...)` for unexpected ones.
- **Canonical values only**: genres from `GENRE_*` constants, formats from the
  mediavocab enums (`PictureFormat`, `ProgrammeFormat`, `AccessibilityKind`,
  `Structure`). Never emit ad-hoc strings.
- No meta-commentary in code/docs/commits — describe the current state.
